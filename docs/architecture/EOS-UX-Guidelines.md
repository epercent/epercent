# EOS UX Guidelines

Version: 0.20.0

## Executive Hierarchy

Every executive screen should answer:

- What is happening?
- What needs attention?
- What decisions are required?
- What business value is being created?
- What should happen next?

## Status Language

Do not show executive users:

- None
- Null
- Undefined
- Unknown Object

Use:

- No Action Required
- Awaiting Review
- Pending Assessment
- Operational
- Monitoring
- Healthy
- Requires Attention
- Action Recommended
- Review Required
- Critical

## Hover Intelligence

Important items must explain their purpose in executive language. Required concepts include:

- Health Score
- Operational Status
- Lifecycle Status
- Second Balance Sheet
- Digital Twin Asset
- Enterprise Object
- Knowledge Object
- Program
- Milestone
- Capability
- Workflow
- Event
- Risk
- Attention Level
- Recommended Action
- Progress

## Presentation Mode

Presentation Mode should:

- Reduce clutter.
- Increase KPI emphasis.
- Keep navigation simple.
- Use premium spacing.
- Hide low-value operational detail where practical.
- Preserve status and executive decision context.

## Navigation

Mission Control should use the Digital Headquarters navigation model:

- Executive Command Bar for headline context and command/search.
- Digital Headquarters Lobby as the default opening experience.
- Primary Workspace Rail for top-level workspaces.
- Context Navigation for active-workspace routes only.
- Breadcrumbs on every screen.

Hover should explain purpose. It should not navigate or hide important context.

## Accessibility

Screens must preserve:

- Keyboard navigation.
- Visible focus rings.
- Screen-reader labels where practical.
- Tooltip access through keyboard focus.
- Responsive layouts.
- High contrast text.
